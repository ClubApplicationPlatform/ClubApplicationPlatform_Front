# 프로젝트 현황
> 두레가 코드를 읽고 쓴 초안입니다. 틀린 곳은 팀이 고쳐 주세요. (작성: 2026-11-05)

## 한 줄 소개
**JoinUs**는 흩어진 대학 동아리 모집 정보를 한곳에 모은 웹 플랫폼입니다. 학생은 동아리를 찾고, 지원하고, 면접 일정을 고르고, 결과를 확인합니다. 운영진은 지원자·질문·모집 일정·공지·면접을 관리합니다. (근거: `ClubApplicationPlatform_Front/README.md`)

## 구성
- **ClubApplicationPlatform_Front**
  - 무엇: 웹 프론트엔드
  - 기술: React 19 · TypeScript · Vite 6 · TailwindCSS 4 · Zustand · React Router 7 · Radix UI
  - 실행: `npm install` → `npm run dev`
- **ClubApplicationPlatform_Server**
  - 무엇: REST API 서버
  - 기술: Java 17 · Spring Boot 3.3.4 · Spring Data JPA · Spring Security · jjwt · springdoc(Swagger)
  - DB: dev는 로컬 MySQL(`club` DB), test는 H2, prod는 Render + PostgreSQL (`application.yml`)
  - 실행: `./gradlew bootRun` (dev 프로필이 기본값이라 로컬 MySQL 필요) 또는 `Dockerfile`로 빌드(8080 포트)
- **demo-repository**, **literate-winner-demo-repository**
  - GitHub 기본 데모 템플릿(index.html + Actions 2개)입니다. 프로젝트 코드와는 관련이 없어 보입니다.

## 만들다 만 것 · 비어 있는 곳
**프론트–서버 연결**
- 프론트가 서버를 호출하는지 확인 필요. `axios`는 의존성에 있지만, 데이터 파일은 `local*`/`mock` 이름입니다.
- 지원 상태값이 서로 다릅니다.
  - 프론트: `pending / document_passed / interview_scheduled / accepted / rejected` (`types/application.ts`)
  - 서버: `PENDING / PASSED / FAILED / CONFIRMED / DECLINED` (`entity/ClubStatus.java`)
- 지원서 답변 저장 위치가 없습니다. 프론트 `Application`에는 `answers`·학번·연락처·면접 슬롯이 있지만, 서버 `Application` 엔티티에는 `userId, clubId, status, message`만 있습니다. `QuestionAnswer.java`는 DB에 저장되지 않는 일반 클래스입니다.
- 면접 모델이 다릅니다. 프론트는 정원이 있는 "슬롯"이고, 서버 `Interview`는 지원서 1건당 일정 1개입니다. 정원 개념은 서버에서 찾지 못했습니다.
- 서버에서 찾지 못한 API
  - 알림
  - 공지 수정·삭제
  - 동아리 소개 정보 수정
  - 관련 근거: `build.gradle`에 websocket 의존성은 있으나 사용처를 찾지 못했습니다.
- 권한 표기가 다릅니다. 프론트는 `"admin"`, 서버 `Role`은 `ADMIN / LEADER / USER`입니다.

**API 경로 · 문서**
- 접두사가 섞여 있습니다.
  - `/api/v1/...`: Application, User, Wishlist, Auth (`ApiPath.java`)
  - `/api/...`: Club, Notice, Interview
  - `/clubs/...`: Search, Admin, Question
- 서버 README가 현재 코드와 다릅니다.
  - 인메모리 저장소, `ClubApplication*` 파일명, `/api/applications` 경로로 적혀 있습니다.
  - README는 `result=pass|fail`이지만, 코드는 `passed|failed`를 받습니다.
- 프론트 README와 실제 코드도 다릅니다.
  - 페이지 경로: README는 `/apply/:clubId`, `/admin/applicants` 등이고 실제 라우트는 다릅니다.
  - 기술 스택: README에 적힌 React Hook Form · Yup · Day.js가 `package.json`에 없습니다.

**인증 · 보안**
- 토큰 인증이 실제로 적용되는지 확인 필요.
  - 커밋 "token 기능 잠시 비활성화"(2025-05-15)가 있습니다.
  - User·Wishlist API는 `userId`를 쿼리 파라미터로 받습니다.
- `POST /api/v1/users`는 `User` 엔티티를 그대로 저장합니다. 비밀번호가 암호화되지 않습니다 (`UserService.createUser`).
- `GET /clubs/admin/users`는 `User` 엔티티를 그대로 반환합니다. 응답에 password 필드가 포함됩니다 (`ClubAdminController.java`).
- 프론트에서 `/clubs/:clubId/manage` 등 대부분의 라우트는 로그인 검사가 없습니다 (`App.tsx`).

**하드코딩 · 임시 코드**
- `ClubService.toListResponse`
  - `adminId = "sg_lead"` 고정
  - id를 `"sg01"` 형식으로 생성
  - 기본 이미지 경로 `../../public/assets/smartGrid.png`
  - 태그를 "스마트그리드/에너지/로드맵" 기준으로 생성
- 이미지 업로드: 로컬 `uploads/` 폴더에 저장하고, URL에 "정적 리소스 매핑에 맞게 수정"이라는 주석이 있습니다 (`ClubService.uploadClubImage`).
- 프론트 하드코딩 데이터: FAQ·사이트 공지·카카오 링크 (`lib/faqData.ts`, `siteNotices.ts`, `kakaoLinks.ts`) (추정)
- 빈 주석 `//클럽 Q&A` (`ClubSearchController.java`), 주석 처리된 코드 (`ClubSearchService.java`)
- 예외 처리 방식이 일부 다릅니다. Notice·Interview·Wishlist 서비스는 `RuntimeException`을 던져 404 대신 500이 될 수 있습니다 (추정).

**DB 스크립트**
- `schema.sql`이 엔티티와 다릅니다.
  - Clubs `type`/`status` enum 값이 다름
  - `member_count`·`recruiting` 컬럼 없음
  - Club_Question의 `qid`/`answer`와 엔티티의 `id`/`maxLength`가 다름
- `data.sql`
  - 비밀번호를 평문 `'1234'`로 넣습니다. 로그인 시 `passwordEncoder` 검증을 통과하지 못할 것으로 보입니다 (추정).
  - Users보다 Clubs를 먼저 INSERT합니다.
- 두 스크립트가 실제로 실행되는지 확인 필요.

**정리할 파일**
